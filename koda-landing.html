Fraud engine

Built to be lied to.

Screenshot fraud exists because merchants verify against customer-side artifacts. KODA's truth is merchant-side, operator-issued, device-attested — a fraudster would have to forge an SMS into your own phone.

Code replay
Global Replay Index — every code is single-use per merchant, forever, across all five doors. A code verified manually is dead to the API too.
Stolen code
Payer-number suffix must match the checkout identity, with exact amount and a tight time window. Mismatch → challenge: "confirm the last 3 digits of the paying number."
Forged screenshot
A screenshot is never accepted as proof on its own. Vision forensics feed the risk score — the truth is always the merchant-side ledger.
Spoofed SMS
Sender-ID allowlist, grammar validation, and the balance-chain defence (shown right) → the fake message is quarantined and the merchant alerted.
Pay, then reverse
Reversal SMS are parsed too and fire payment.reversed. KODA can't stop an operator reversal — it makes you the first to know.

Every genuine operator SMS carries the running balance, so each new balance must equal the previous balance plus the amount. A spoofed SMS breaks that arithmetic. The operator's own bookkeeping is the firewall — and it works identically for bKash in Dhaka and Orange Money in Kinshasa.

The agent mesh

Nine agents. Every decision auditable.

A LangGraph mesh supervises every verification. Agent law: every autonomous confirmation writes its full decision trace to an append-only store — a verification you cannot audit is a verification you cannot defend.

Structures SMS; detects operator format drift; regenerates + canary-ships template packs worldwide, OTA.

K-02

MatchMaker

Code↔ledger↔intent↔amount↔window↔suffix matching. Repairs customer typos up to edit distance 2.

~40-feature risk score per match; Global Replay Index; retrained per corridor — Kinshasa fraud ≠ Dhaka fraud.
